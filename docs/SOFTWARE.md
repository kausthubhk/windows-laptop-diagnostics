# Software and tool inventory

This ledger distinguishes programs already present, portable tools downloaded and run, installations performed during a prior session, failed attempts, and tools that were never run. “Observed present” does not establish who installed a program or when. Versions and statuses below come from captures dated 10–15 October 2026 and a narrow review of session history matching this workspace; unrecorded history remains unknown.

## Windows components and scripts

- **Windows 11 Home Single Language, build 26200 (64-bit):** recorded on 14 October. Windows-provided commands used included `WinSAT.exe`, PowerShell/CIM (`Get-CimInstance`), performance counters (`Get-Counter`), `powercfg /batteryreport`, `powercfg /energy`, Event Viewer queries, and Windows Management Instrumentation battery providers. No Windows component installation or configuration change is evidenced.
- **PowerShell 7.6.5:** version recorded in a 14 October inventory collector. Other sessions invoked Windows PowerShell as well. Neither installation date nor updates to PowerShell are evidenced.
- **Python and Git:** no historical version or install record was found in the retained diagnostics. Python can run the repository comparison/export scripts in this current environment, but that does not establish that a specific version was installed during the diagnostic sessions. Git is present in the current workspace, with no record here of when or how it was installed.
- **Local PowerShell/Python scripts:** the historical `ram_suite.ps1`, `monitor_ram.ps1`, and `compare_ram.py` were authored in the workspace for memory-copy/paging capture and comparison. New recovery scripts now live under `scripts/`; they are local project files, not operating-system installations. They write to ignored `local-results/`.
- **Windows Memory Diagnostic (`mdsched.exe`):** built into Windows. The user reported running it after a restart. The logs contain a scheduled-test event and a subsequent reboot, but the post-sign-in queries returned no result record; completion and pass/fail remain unknown.
- **Dell preboot diagnostics/ePSA:** available through Dell firmware; not run in the recorded sessions.

## RAM tools

- **WinSAT memory (`winsat mem`):** Windows component, not separately installed. It was run repeatedly for the 10 September 2×4 GiB baseline, 14 October 1×8 GiB setup, and 15 October 8+4 GiB setup. The final comparable matrix used five elevated WinSAT runs per configuration. The 15 October command used `mem -mint 10 -maxt 20 -buffersize 256MB`. Earlier non-elevated attempts were fallback managed-buffer copies and are not WinSAT results. Microsoft documents WinSAT as a memory-bandwidth test requiring an elevated prompt: [WinSAT mem command](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/winsat-mem).
- **Intel Memory Latency Checker (MLC) v3.13:** portable utility downloaded from Intel to the user Downloads area, outside the workspace, and run for four modes × five repetitions in the final elevated matrices. The 15 October run record says the executable had a valid Intel signature and that no driver was installed or loaded by the runner. MLC is licensed under Intel's limited tools license; it is not included in this public repository. Obtain it from [Intel's MLC download page](https://www.intel.com/content/www/us/en/download/736633/intel-memory-latency-checker-intel-mlc.html) and review the license/readme. Intel describes it as a latency/bandwidth measurement tool: [MLC overview and command reference](https://www.intel.com/content/www/us/en/developer/articles/tool/intelr-memory-latency-checker.html).
- **Phoronix Test Suite (PTS) v10.8.6:** its console was available during the earlier baseline work. The retained files do not establish whether it was installed during these sessions or was already present. The attempted CacheBench invocation returned invalid-argument/syntax notices, so no CacheBench measurement was produced. PTS's `local/intel-mlc-1.1.0` attempted to download MLC v3.10 but failed; output explicitly says the test was not installed. A memory-suite identifier was also rejected as invalid. No valid PTS score is included. Project/license information: [Phoronix Test Suite source](https://github.com/phoronix-test-suite/phoronix-test-suite).
- **CPU-Z v3.01 portable ZIP:** official English x86/x64 ZIP downloaded to the workspace and extracted; this was not a conventional installed application. Its official hash matched CPUID's published checksum, and the executable had a valid CPUID signature. It was run elevated once on 14 October to save SPD/channel text. The before/after inventory found no CPU-Z process, driver, service, or temporary directory remaining. CPU-Z's low-level SPD access can interact with a kernel driver; see the [CPUID CPU-Z page](https://www.cpuid.com/softwares/cpu-z.html) and local source notes in the private original capture. The extracted binaries and full report are excluded from this public copy.
- **Limited memory pattern screen:** a project-specific managed-buffer test completed eight pattern passes over one 256 MiB allocation (2 GiB written and checked), with zero mismatches. It did not test all physical RAM and is not a system-wide memory certification. The new `scripts/test-memory-patterns.ps1` exposes this bounded check as an optional local tool; only syntax and safety-guard checks were performed on the recovery script, not a new memory-pattern run.
- **Public-results exporter:** `scripts/prepare-public-results.py` is a standard-library Python script that rebuilds the explicit sanitized historical allowlist. Its `--run-dir` and `--label` options can export a reviewed new capture with its own manifest. The historical root manifest remains the record of the existing curated results. Review each export before sharing; the script does not make a raw capture safe by itself.

## SSD tools

- **CrystalDiskInfo v9.9.2:** downloaded from the CrystalMark project's distribution and installed through the official `CrystalDewWorld.CrystalDiskInfo` Windows Package Manager listing in a 19 September session. The installer was signature-checked as valid and signed by CrystalMark Inc. The app was opened and a SMART text report was saved outside this workspace. It is a read-oriented status viewer; its report was not copied into the public result set because it contains more device detail than needed.
- **CrystalDiskMark v9.0.3:** downloaded through the official `CrystalDewWorld.CrystalDiskMark` listing and installed in the same session; installer signature was valid and signer was CrystalMark Inc. It was deliberately **not launched for a benchmark**, because the benchmark writes test data to the drive. No CrystalDiskMark score exists in this record. Historical installation is supported by the 19 September session log, not by files in the RAM workspace.
- Current vendor source pages: [CrystalDiskInfo](https://crystalmark.info/en/software/crystaldiskinfo/) and [CrystalDiskMark](https://crystalmark.info/en/software/crystaldiskmark/). The install source was Winget metadata plus signed CrystalMark installers. No installer or executable is included here.

## Battery and Dell tools

- **My Dell / Dell Power Manager features:** the Microsoft Store-signed My Dell package was observed at version **2.2.6.0** on 15 October. Its in-app update flow was run because opening the app required it; the package still reported 2.2.6.0 afterward. This does not show an upgrade occurred. The battery page reported “EXCELLENT” health and “Dell Battery: Yes.” No battery-care or Windows power setting change was recorded.
- **Dell SupportAssist v5.2.1.2141:** already present in the installed-program inventory. SupportAssist's battery-specific functional test and charger test both passed on 15 October. These are functional checks, not a physical battery authentication or full-capacity test. [Dell SupportAssist information](https://www.dell.com/support/kbdoc/en-us/000130387/dell-supportassist-formerly-dell-system-detect-overview-and-common-questions).
- **Dell Power Manager Service v3.18.0:** official Dell installer downloaded, hash and Authenticode verified, then launched once on 15 October. Installation failed at the actual `IsMyDellInstalled` check because My Dell was present (MSI exit 1603 / return value 3). No service install, uninstall, repair, driver/firmware update, restart, or power setting change followed. Dell's current product notes that these features have moved into Dell Optimizer/MyDell; see [Dell's service page](https://www.dell.com/support/home/en-us/drivers/driversdetails?driverid=2963m) and [user guide](https://www.dell.com/support/manuals/en-us/power-manager/power-manager_ug/install-uninstall-and-upgrade-dell-power-manager?guid=guid-3f799294-5989-47a0-aaa7-4821b1225d86&lang=en-us).
- **PowerToys Awake:** the power-efficiency report recorded an Awake request during the battery session. The evidence shows it was active, not that it was installed or changed during these sessions. Display and sleep timeouts were disabled in the captured power report; no evidence identifies who changed them or when. The diagnostic sessions did not change these settings.
- **Native battery reporting:** Windows `powercfg /batteryreport`, `powercfg /energy`, WMI/CIM and performance counters were used. Report generation and telemetry were read-only. Battery temperature was unavailable from the queried provider. A complete charge/discharge capacity test and ePSA were not run. Future collection is documented in `docs/RECOVERY.md` and `scripts/collect-battery.ps1`.

## Downloads and installs not made by the project

This ledger does not claim that only the listed software exists on the laptop. It covers only evidenced tools from the memory, SSD, battery, and directly related diagnostics. Intel MLC, CPU-Z, CrystalDiskInfo, CrystalDiskMark, and Dell's Power Manager Service installer files were handled on the personal machine outside the public repository where stated. The Dell Service install failed; CrystalDiskMark was installed but its write benchmark was not run. Phoronix install provenance, Python/Git installation history, and unrelated applications remain unknown. No private session log is copied into the repository.
